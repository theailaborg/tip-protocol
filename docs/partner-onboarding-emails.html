1. Test network onboarding

Subject: TIP test network: your node credentials and setup steps

Hi {{PARTNER}} team,

Your node is registered on the TIP test network and ready to bring online. The test network is completely separate from production: its own genesis, its own identities, its own data. Nothing you do here can affect the live chain, so it is a safe place to get familiar with running a node.

Attached: one password-protected zip (AES-256). The password comes over a separate channel, not in this thread. Everything is inside it because two of the files are credentials.

  • node.env - your node configuration, mostly filled in. Holds live API credentials, so keep it chmod 600 and never commit it.
  • <node-id>.tip.json - your node key. Runs the node. Treat it like an SSH host key: chmod 600, never commit it, never forward it.
  • id-<REGION>-<id>.tip.json - your organization identity. This is your company on the network; it signs content as you. It is not needed to run the node, so keep it off the node host, wherever you keep company signing material.
  • genesis.json - the test network genesis
  • README.md - what to do, in order

To open the zip you need a tool that supports AES: 7-Zip on Windows, Keka or The Unarchiver on macOS. The built-in extractors on both do not.

Please store both in whatever you use for company secrets and keep an offline backup before you deploy. If either is ever lost or exposed, tell us straight away so we can act on it with you.

Where to start

Start with README.md in the bundle. The node is open source, so you can read everything before you provision anything:
https://github.com/theailaborg/tip-protocol

  1. Hardware and OS, please check before provisioning; the figures are measured from our production federation:
    https://github.com/theailaborg/tip-protocol/blob/main/docs/NODE_REQUIREMENTS.md
  2. The deploy itself, section Production Federation Deploy (0 to live):
    https://github.com/theailaborg/tip-protocol/blob/main/docs/DEPLOYMENT.md
  3. Overview and repo layout:
    https://github.com/theailaborg/tip-protocol/blob/main/README.md

Two things that catch almost everyone:

  • The container runs as uid 1001. Every file it reads must be owned by 1001.
  • Run mkdir -p logs && sudo chown -R 1001:1001 logs before the first boot, or the log directory silently stays empty.

And please do not run npm run seed or seed:fresh. That mints a fresh genesis and new identities, and your node will not be able to join us.

Three values you need to set in node.env (marked CHANGE_ME): your public IP, your public URL, and a database password of your choosing.

node.env also contains TIP_CLASSIFIER_KEY, which lets your node reach our content classifier. Please treat it as a credential: keep the file chmod 600, do not commit it, and do not use the key from anywhere other than your node. It is shared infrastructure, so if it leaks we have to rotate it for everyone.

Please send back

To finish connecting you and add you to our monitoring, we need:

  1. Public IP of the node host - we allow-list it and our nodes dial you back.
  2. Domain name for the node, if you are using one (e.g. tip.yourdomain.com), otherwise we use the IP.
  3. Confirmation that inbound TCP 4000 and 4001 are open to the internet. 4000 is the API, 4001 is peer-to-peer. Without 4001 you can reach us but we cannot reach you, and you will not fully join.
  4. Your node's bootstrap address once it is running:
    curl -s localhost:4000/health | grep -o '"bootstrap_addr":"[^"]*"'
  5. A contact for node issues - name and email, ideally someone reachable if the node misbehaves.
  6. Which region/provider you are hosting in - helps us interpret latency.
  7. Your real company registration details, for the live network later: full legal name exactly as registered, registration number, date of incorporation, country. We could not find you in the public register, so your test identity uses a placeholder number. That is fine for testing and not fine for production, where the value is permanent and uncorrectable. Please confirm these from your own records rather than us looking them up.

node.env already contains TIP_METRICS_TOKEN, which lets our monitoring scrape your node's /metrics endpoint so your node's health shows on our dashboards alongside ours. Please leave it set: without it we cannot tell you your node is unhealthy before you notice. /metrics rejects any request that does not present this token, so the endpoint stays closed to everyone else. Once we have items 1 to 3 we will add your node to our scrape config.

How to confirm you joined

Run these on the node host (over SSH), where localhost is the node:

curl -s localhost:4000/ready        # ready:true, halted:false, join_state:ready
curl -s localhost:4000/health       # peers.connected >= 1
curl -s localhost:4000/v1/state-root

From your laptop or anywhere else, use the node's own address instead. That also double-checks that port 4000 is genuinely open, which localhost cannot tell you:

curl -s http://YOUR_NODE_IP:4000/ready

The state_merkle_root should match ours at the same round. Expect the first boot to sit in catching_up briefly while it syncs; that is normal.

If anything does not match, send us the output of those commands plus docker logs tip-node --tail 100 and we will take a look.

Setup

Follow README.md in the bundle. The node is open source:

  • Repo: https://github.com/theailaborg/tip-protocol
  • Hardware and OS: https://github.com/theailaborg/tip-protocol/blob/main/docs/NODE_REQUIREMENTS.md

Production notes beyond the test setup:

  • NODE_ENV=production
  • TIP_CORS_ORIGINS must list real origins, never *
  • node.env carries TIP_CLASSIFIER_KEY, our content classifier credential. Keep the file chmod 600, never commit it, and use the key only from this node. It is shared infrastructure: a leak forces a rotation for every operator.
  • the container runs as uid 1001; every file it reads must be owned by 1001
  • run mkdir -p logs && sudo chown -R 1001:1001 logs before first boot
  • never run npm run seed or seed:fresh
  • take a backup of both key files before you start, stored offline

Before you deploy, please confirm

  1. Inbound TCP 4000 and 4001 reachable from the public internet
  2. Static or elastic IP, not one that changes on reboot
  3. Host meets the spec:
    https://github.com/theailaborg/tip-protocol/blob/main/docs/NODE_REQUIREMENTS.md
  4. You hold an offline backup of both key files

Once you are up

Run these on the node host (over SSH), where localhost is the node:

curl -s localhost:4000/ready        # ready:true, halted:false, join_state:ready
curl -s localhost:4000/health       # peers.connected >= 1
curl -s localhost:4000/v1/state-root

From anywhere else, use the node's own address. That also confirms port 4000 is genuinely reachable, which localhost cannot tell you:

curl -s http://YOUR_NODE_IP:4000/ready

Please send us:

  1. The public IP of the node host. It must be static or elastic: peers store it, so an address that changes on reboot drops you out of the mesh.
  2. The domain name you are serving the node on, if any (e.g. tip.yourdomain.com). This is what goes in TIP_API_ENDPOINT, and the node announces it on chain as its public API origin, so it needs to be the address you intend to keep.
  3. Your state-root and bootstrap_addr from the commands above.

We hold 1 and 2 in our operator records, allow-list the IP so our nodes dial you back, and add the node to our monitoring. Tell us if either ever changes.

We will confirm your state_merkle_root matches ours at the same round. node.env already contains TIP_METRICS_TOKEN, so your node's health appears on our dashboards next to ours; please leave it set. /metrics rejects any request that does not present it.

Expect the first boot to sit in catching_up while it syncs from a peer. On production that takes longer than it did on test.

Operational expectations

Your node participates in consensus, so its availability affects the network, not only you. Please let us know in advance of planned downtime, and reach out promptly if the node is unhealthy. We monitor and will contact you if we see a problem first.
